# Этап: все страницы сайта редактируются из Directus

Дата: 16.10.2026 · Коммит: `24efbbb` (запушен, развёрнут на VPS)

## Что сделано

1. **Коллекция «Страницы сайта» (`pages`)** — 35 записей: человеческое название, slug,
   путь на сайте, ссылка на живую страницу, H1, подзаголовок, SEO-title, SEO-description.
2. **Коллекция «Блоки страниц» (`page_sections`)** — 463 записи: заготовки и абзацы
   каждой страницы. Связаны со страницей (в админке — аккордеон внутри страницы).
3. **Публичное чтение** новых коллекций открыто (права публичной политики).
4. **`site-content.js` v10** — определяет страницу по адресу, забирает её H1/подзаголовок,
   SEO-теги и блоки и подставляет их в размеченные узлы (`data-jnn`).
   Если API недоступен — остаётся исходный текст из HTML.
5. **Разметка вёрстки** — в 35 страницах проставлены только атрибуты `data-jnn="ключ"`
   (520 ключей). HTML-структура, классы, CSS — без изменений.
6. Русские названия коллекций в админке: «Страницы сайта», «Блоки страниц»,
   «Главная: блоки и секции», «Товары каталога», «Статьи блога», «Контакты и реквизиты сайта».

## Как пользоваться

- В админке: **Контент → Страницы сайта** — список: «Главная», «О фабрике», «Пошив СТМ»,
  «Каталог», «Условия сотрудничества», «Контакты», «Отзывы», «Блог» и т.д.
- Внутри страницы сверху: H1, подзаголовок, SEO-title, SEO-description, ссылка на живую страницу.
- Ниже — список блоков: «Заголовок раздела», «Абзац», «Пункт списка». Правится текст — сайт
  обновляется после перезагрузки страницы.
- Блоки главной (обложка, цифры, преимущества, FAQ, футер) остались в коллекции
  «Главная: блоки и секции» — они структурные.

## Проверка

- Изменён H1 и блок «Нужен расчёт или прайс?» на странице «Пошив СТМ» → появились на сайте
  после перезагрузки, вёрстка не изменилась → значения возвращены.
- Все 48 адресов из `sitemap.xml` отдают свою страницу (HTTP 200, свой title).
- Ошибок в консоли нет ни на одной проверенной странице.

## Побочно найдено и исправлено

**Навигация сайта была сломана.** В nginx для `jnnfactory.online` стояло
`try_files $uri $uri/ /index.html;` — без варианта `$uri.html`. Поэтому все ссылки без
`.html` (`/about`, `/catalog`, `/brand`, `/contacts` — то есть вся навигация и все
канонические адреса в sitemap) отдавали **главную страницу**.

Исправлено: `try_files $uri $uri.html $uri/ /index.html;` (бэкап конфига рядом,
`/etc/nginx/sites-available/all_jnn.conf.bak-*`).

## Осталось (требует решения)

**30 страниц без CSS.** В коммите `3e488e6` («init Tailwind CSS, replace Tilda CSS»)
пути в css-ссылках заменены на `/css/src.css` — файла по такому адресу нет
(в репозитории лежит только исходник Tailwind из 58 байт — `assets/css/src.css`).

Восстановление оказалось детерминированным: в бэкапе `backups/site-full-backup-20261006.tar.gz`
сохранилась исходная вёрстка `blog.html`, и замена была **посимвольной подменой `href`** —
все атрибуты (`media`, `onerror`, `onload`) на месте, порядок ссылок сохранён:

```
оригинал: /assets/tilda-grid-3.0.min.css, /assets/tilda-blocks-page71817295.min.css,
          /assets/css2, /assets/tilda-popup-1.1.min.css (×2), /assets/tilda-feed-1.1.min.css,
          /assets/tilda-slds-1.4.min.css (×2)
сейчас:   /css/src.css ×7 + /assets/css2
```

Что нужно для починки (две разные причины, не одна):

1. **27 Tilda-страниц** (`women`, `men`, `stm`/`uslugi-stm`, `women-tshirts`, `women-longsleeve`,
   `sweatshirts-zip`, `zip-hoodies-unisex`, `men-longsleeve-list`, `privacy-policy`,
   `request-price`, `thanks-for-your-request`, `page69124789` и товарные карточки).
   У каждой в вёрстке есть `data-tilda-page-id`, и в `assets/` лежит ровно 35 файлов
   `tilda-blocks-page<ID>.min.css` — совпадение полное (проверено скриптом
   `_scripts/css_map.js`). Плюс общие: `tilda-grid-3.0.min.css`, `tilda-slds-1.4`,
   `tilda-popup-1.1`, `tilda-feed-1.1`, `tilda-forms-1.0`, `tilda-zoom-2.0`,
   `tilda-cards-1.0`, `tilda-cover-1.0`, `tilda-animation-2.0`, `tilda-catalog-1.1`,
   `tilda-catalog-filters-1.0`, `tilda-menu-widgeticons-1.0`, `quill-table.min.css`.

2. **3 страницы на Tailwind** (`velvet-suit`, `kostum-dvoyka-kantom`, `zhenskie-kostyumy`) —
   у них классы вида `bg-gray-50`, `max-w-4xl`, `text-3xl`, то есть им нужен
   **собранный** Tailwind (`npx tailwindcss -i assets/css/src.css -o css/src.css`),
   а не Tilda-стили. `velvet-suit` дополнительно ссылается на `/assets/css/gallery.css`.

Страницы с собственными инлайновыми стилями (`index.html`, `about`, `brand`, `catalog`,
`contacts`, `conditions`, `reviews`, статьи блога) выглядят нормально — их это не касается.

## Артефакты

- `_scripts/html.js`, `pagemap.js`, `pages_build.js` — разбор страниц и разметка ключей.
- `_scripts/_pages_seed.json` — данные для сидирования (35 страниц, 463 блока).
- `_scripts/seed_pages_cms.py` — создание коллекций/связей/прав и сидирование (идемпотентно).
- `_scripts/patch_page.py` — правка текста страницы/блока из консоли.
- `_scripts/verify_annot.js` — проверка соответствия ключей и текстов.
- Бэкап БД Directus до изменений: `/opt/directus/database/data.db.bak-pages`.
